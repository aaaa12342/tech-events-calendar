# P0 回归验证

在项目根目录运行：

```sh
python -B -m unittest discover -s tests -v
node tests/event-status.test.js
node tests/event-view.test.js
node tests/page-controls.test.js
```

测试不访问网络、不改写正式活动数据；Python 文件测试使用 tests 目录中的临时目录。

修复后的行为：

- `hackathons.json` 的 `source_cache` 保存各来源最近一次成功结果，避免跨源去重后丢失备用条目。首次运行从已有 `events` 恢复缓存。
- 来源异常、无效数据、已有缓存的来源突然返回零条时，回退缓存；缓存展示时按活动时间过滤过期条目。全部来源失败时退出码为 1，原文件保持不变。
- 输出经过校验后使用同目录临时文件原子替换，写入失败不会截断原文件。
- 活动阶段与报名状态分别展示；开始日从北京时间零点生效，结束和报名截止日期到当天最后一毫秒有效。缺日期显示待确认，`ended` 只表示本届报名结束。
- 有结束日期时，以结束日期判断是否超过 30 天保留窗口；无结束日期且有开始和报名信息时，保守保留，避免误删长期活动。

新增 `event-status.js` 是页面必需文件，部署时需要与 `index.html` 一起发布。每日更新工作流在抓取前运行这些测试。

搜索筛选与更新提示：

- 搜索名称、主办方、城市、地点和分类，忽略英文大小写；空格分隔的关键词需要全部匹配。
- 报名状态、仅线上、隐藏已结束活动和分类可以组合使用。“可报名”只包含明确有未过期截止日期的活动；信息不足的活动归为待确认。
- 清除筛选会重置关键词、报名状态、线上限制、隐藏已结束和分类，保留城市优先及排序选择。
- 更新时间按北京时间解析，超过 48 小时提示陈旧；来源异常时显示警示。新输出中的 `source_status` 记录各来源本次状态、最近成功时间和条数；旧数据无法确认的成功时间显示未知。
- 来源全失败时不改写正式文件，因此页面不会获得这次尝试记录，但会依据旧更新时间显示陈旧提示。
- `event-view.js` 也是页面必需文件，部署时须一同发布。页面测试使用模拟 DOM，未替代真实浏览器视觉检查。
